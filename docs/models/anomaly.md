## Limitations
- All data is synthetic: the scores say how unusual a customer-month is among its peers in the generated data, not how a real customer base behaves.
- The four graph features are one snapshot of the last network / GDS run shared by every month, so older months see information from after they happened (temporal leakage).
- No night-time signal is planted in the synthetic data (every planted typology happens in daylight), so night_ratio is expected to add almost nothing.
- Merchant-like benign customers (many counterparties, large flows) score high: expect false positives that no rule produces.
- The threshold is a fraction of the samples, so every run raises exactly that many alerts, even when nothing is unusual.
- ANOMALY items also enter the pinned case features alerts, distinct_rules and alert_amount_log (the anomaly alert carries the whole month, so money already in RULE alerts is counted twice); with ml.anomaly.features=off the case scores of cases holding an ANOMALY item still change.
- On this synthetic data the rules already catch every suspicious scenario, so the number of scenarios only the model catches is expected to be zero; the model's value is as a ranking feature and as a second opinion.
